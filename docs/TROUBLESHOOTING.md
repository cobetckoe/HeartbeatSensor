# 常见问题速查

先接串口看日志（判读方法见 [SERIAL-LOG.md](SERIAL-LOG.md)），绝大多数问题
一行日志就能定位。下表按「现象」查。

---

## 屏幕

| 现象 | 处理 |
|---|---|
| 花屏 / 斜纹 / 撕裂 | 检查有无**无参** `SPI.begin()`（会把 SCLK 从 GPIO6 挪到 GPIO4）；脏矩形起始列是否为偶数 |
| 全白 / 全黑 | 量背光 GPIO10 是否为高；`initR(INITR_BLACKTAB)` 参数是否正确 |
| 帧率低 | 确认 `TFT_SPI_HZ` 为 20 MHz；看每帧变化面积是否超预算（见 [DISPLAY.md](DISPLAY.md)） |
| 开 WiFi 后屏幕卡住不动 | 看 `[GATE]` 行：**`fh` 一直涨** = 433 接收模块被 2.4 GHz 压得自激，属射频/摆位问题（挪远天线、加电源去耦）；**`fh=0`** = 只是偶发延迟，正常。机制见 [DISPLAY.md](DISPLAY.md) 第 3 节 |
| 屏幕偶尔卡一下，从机在不在都一样 | 查 `[HEALTH]` 的 `nz`：噪声突发被误判成帧。若 `nz` 大而 `ook` 小，是射频自激 |
| 目标颜色莫名变化 / 光点跳动 | 已由航迹跟踪消除；若仍出现，看是否为两个真实目标重叠 |
| 光点持续小幅抖动 | 传感器 10 Hz、屏幕 ~50 Hz，同一采样被重复画 5 帧。现有 EMA 平滑（系数 0.45）应已消除 |

## 雷达

| 现象 | 处理 |
|---|---|
| **雷达不出数** | 接串口看 **[RADAR] ok= bad= raw=** 这一行（每 60 s 一行）：<br>`raw` 不涨 → 物理层没通（TX/RX 接反 / 没供电 / 传感器还在启动）<br>`raw` 涨但 `ok` 不涨 → 波特率不对或帧被截断<br>`ok` 涨但屏上无点 → 已进入算法层，与 UART 无关 |
| 读数不稳 | **雷达必须接 5V**，3.3V 供电会导致读数不稳甚至不出数 |
| 读数周期性跳 0 | 传感器漏采一次（该槽 x=y=0）；已有 350 ms 短时保持 |
| 角度偏一点 | 原按 2° 栅格对齐后查表；现为 2° 查表 + 线性插值，量化误差 ~0.02° |

## 433 无线 / 从机

| 现象 | 处理 |
|---|---|
| 某个防区偶发整轮丢失 | 可能是队列互挤（已修：`OOK_QUEUE_LEN` 16 槽 = 4 区 × 3 帧 + 余量） |
| A 区一动 B 区就掉线 | 典型的**相位碰撞**：两台从机同时发，后一帧的前导被前一阵发的 SPI 推屏打掉。看四个防区的 `f=` 是否相差很大 |
| 从机反复重启 | `[HEALTH]` 的 `rst` 持续上涨 + `rbt` 很小。最常见：433 发射瞬间把 Vcc 拉塌导致欠压复位 |
| 串口有 `[OOK]` 但防区一直离线闪 | **ID 不匹配**。对照开机日志 `[ZONE]  #0 id=` 和 `[OOK]` 行的 ID。换芯片/换板后 STC8 出厂唯一 ID 会变，必须重新配对 |
| 一帧都收不到，`nz` 很大 | 433 接收模块自激（干扰 / 天线差 / 供电脏）。`nz` ≈ 0 才是正常 |
| `ovf` 持续增长 | **帧是主机丢的**（RMT 环形缓冲溢出），与射频无关 |
| `crc` 一直涨 | 看 `[FAIL]` 直方图定位是哪道闸门（见 [SERIAL-LOG.md](SERIAL-LOG.md) 的 `[FAIL]` 小节） |

## 构建 / 烧录

| 现象 | 处理 |
|---|---|
| 构建报 `intelhex` 找不到 | 用系统 Python 下的 `pio`，脚本已自动优先选可用的 |
| 报 `.sconsign311.tmp` FileNotFoundError | 删掉 `.pio\build\esp32c3\.sconsign311*` 再构建 |
| **不要同时跑两个 `pio run`** | 会互相破坏 `.pio\build` |
| 找不到串口 | 设备管理器 → 端口；`flash.ps1` 不带 `-Port` 会自动探测 |
| 烧录失败 | 按住 **BOOT** 再点一下 **RESET** 进下载模式；或 `flash.ps1 -Raw` |
| 从机 UV4 `Exit=15`，无日志无产物 | **`slave.uvproj` 带了 UTF-8 BOM**。必须是无 BOM；`build_slave.ps1` 已自动剥离 |
| 从机编译报中文注释语法错误 | 源码被转成 UTF-8。`src/slave/Sources/**` **必须保持 GBK 无 BOM** |
| 文档中文乱码 | `.md` 缺 BOM，PowerShell 按 GBK 读了。写入时用 `UTF8Encoding($true)` |

## 串口

| 现象 | 处理 |
|---|---|
| 一打开串口设备就复位 | 正常：C3 原生 USB，DTR/RTS 会触发复位。用 `utils/serial_monitor.py`（已抑制 DTR/RTS + 自动重连） |
| 想测真实连续运行时间 | 同上，必须用 `serial_monitor.py`，且看 `[HEALTH]` 的 `up=` 是否单调递增 |
| 日志里有 `[E]` 行 | **真故障**。正常构建下 `-DCORE_DEBUG_LEVEL=0` 会把所有 HAL 级 `log_e` 编译掉，出现就是异常 |

## 涂鸦云

| 现象 | 处理 |
|---|---|
| APP 上数字小 10 倍 | DP 的「倍数」填成了 `1`。**必须填 `0`**（涂鸦的「倍数」实际是小数位数）。见 [TUYA-DP-SETUP.md](TUYA-DP-SETUP.md) |
| 扫描二维码加不进 App | 本固件直连云 MQTT，不走 App 配网，**不产生绑定 token**。要进 App 需走云开发 OpenAPI 绑定或自研 App |
| 配网时总是立刻跳到 AP 门户 | 早期 bug（把 `ESP_ERR_WIFI_STATE` 误读成「附近没这个 WiFi」），已修 |
| 开 WiFi 后偶发卡顿 | 见上面「屏幕」一节的 `[GATE]` 行判读，或 [SERIAL-LOG.md](SERIAL-LOG.md) 的 `[GATE]` 小节 |
