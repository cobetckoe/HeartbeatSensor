# 涂鸦 DP 点配置

对应固件 `src/master/TuyaConfig.h` 第 5 节。固件上报 **7 个 DP**，全部只上报（ro）。

## DP 清单

### 布尔型（4 个）

| # | code | 含义 |
|---|---|---|
| 104 | `zone_a_presence` | A 防区有人 |
| 105 | `zone_b_presence` | B 防区有人 |
| 106 | `zone_c_presence` | C 防区有人 |
| 107 | `zone_d_presence` | D 防区有人 |

### 数值型（3 个）

| # | code | 范围 | 间距 | 倍数 | 单位 | 含义 |
|---|---|---|---|---|---|---|
| 101 | `radar_distance` | 0 ~ 800 | 1 | **0** | cm | 最近目标距离（厘米） |
| 102 | `radar_angle` | -90 ~ 90 | 1 | **0** | ° | 最近目标角度 |
| 103 | `radar_targets` | 0 ~ 3 | 2 | **0** | tgt | 目标个数 |

数值型的「倍数」**一律填 `0`**。

> ⚠️ 不要填 `1`。平台这栏虽然叫「倍数」，但接口字段 `scale` 的真实语义是
> **小数位数**：填 `0` 值原样显示；填 `1` 值会被除以 10 后显示（一位小数），
> APP 上的数字会整整小 10 倍。本固件三个点都是整数，所以填 `0`。
>
> ★ 这是**已踩过的坑**：曾把 `radar_distance` 的 scale 设成 1，
>  固件发 180（=180cm）在 APP 上显示成「18.0cm」，整整差 10 倍。

> ⚠️ `radar_targets` 的「间距」填 `2`，固件实际步进是 1。
>   这是平台侧的限制（取值 0/1/2/3 共 4 档，间距 2 时才允许 0 起跳），
>   对只读上报**没有影响**：固件发什么就显示什么，只是 APP 图表在取整时
>   会出现「1 和 2 看起来一样」的错觉。现场以屏幕上的目标数为准。

## ★ 为什么只有 7 个点（曾经的坑）

早期固件上报 **11 个** DP，除了上面 7 个，还多带了 4 个
`zone_a_online` ~ `zone_d_online`（防区从机在线状态）。

**平台上根本没有建这四个点** → 涂鸦云会**静默丢弃**未定义的 DP：
`publish()` 依然返回成功，固件侧看不到任何错误，日志一切正常，
但云端永远收不到 —— 这是最难查的一类失败模式。

所以现在：

- 固件只上报平台上真实存在的 7 个点（`TuyaLink.h` 的 `_report()`
  里 `Item items[4]` 只放 4 条 presence，JSON 缓冲 512 字节）；
- **防区离线状态不再单独上报**。从机掉线时对应防区的 presence 也会变成
  false，APP 上看到的就是「没人」而不是「掉线」。
  现场判断「是没人还是掉线」以**屏幕底部的三态防区条**为准
  （正常 / 离线灰显 / 有人高亮，见 `docs/DISPLAY.md`）。

如果将来平台要加回在线状态，必须**先在平台建点**，再改固件——顺序不能反。

## 建点步骤

### 1. 产品选项

| 项 | 值 |
|---|---|
| 设备类型 | 普通设备 |
| 通讯协议 | Wi-Fi |
| 功耗类型 | 标准功耗 |
| 智能化方式 | 自定义方案 |

### 2. 添加功能

功能定义 → 添加功能，按上面两张表逐条添加。每条填：

| 字段 | 值 |
|---|---|
| 功能类型 | 属性 |
| 功能名称 | 自定 |
| 标识符 | 表中的 `code`，必须逐字一致 |
| 数据类型 | 布尔型 / 数值型 |
| 读写属性 | 只上报 |

### 3. 发布

保存后点「发布到线上」。

## 三元组

配网页填：设备开热点 → 手机连 `Kanchuan-HB-XXXX` → 打开 `192.168.4.1` → 展开「涂鸦云三元组」→ 填 DeviceID / DeviceSecret → 保存。存 NVS，换设备不用重编译。

也可写死在 `TuyaConfig.h`：`TUYA_PRODUCT_ID` / `TUYA_DEVICE_ID` / `TUYA_DEVICE_SECRET`。NVS 优先于宏。

## 数据中心

选「中国数据中心」。选错设备不上线。

## 绑定 App

### 设备调试（现在就能用）

开发者平台 → 产品 → **设备调试** → 选中设备，可看 7 个 DP 实时值，也可手动下发模拟。不需要 App。

### 涂鸦智能 App

**扫码添加不适用本方案。** 设备没有配网环节，开机带三元组直连云 MQTT，不产生 App 配网所需的 token，所以不会出现在 App 的设备列表里。

要进 App，只有两条路：

| 路径 | 做法 | 代价 |
|---|---|---|
| 自有 App / 小程序 | 云项目 → 设备 → 关联自有 App，用 OpenAPI 拉设备列表和控制 | 要开发 App |
| 云开发 OpenAPI | 在云项目「API 调试」里搜「绑定」，用设备绑定接口把 `device_id` 绑到 App 账号的 `uid` | 要写脚本调接口 |

### 想用智能生活 App 扫码添加

必须换成 MCU 标准协议接入（ESP32 + 涂鸦 WiFi 模组 + MCU SDK 串口协议）或 TuyaOS。本固件不适用。
