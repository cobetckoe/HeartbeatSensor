# KC433 无线报文协议 (v1)

主机（ESP32-C3 + OOK 接收头）与从机（STC8G1K08A + OOK 发射头）之间的私有协议。
两端都按本文实现，**改任何一处都必须两端同步改**。

## 1. 编码方式

433M 用的是超再生 / 超外差 OOK 接收头，内部有 AGC。如果连续发相同电平，
AGC 会漂移导致丢位。所以采用 PT2262 / EV1527 那套久经验证的**脉宽编码**：

- 每一位固定占 `4T`，高低电平按比例分配 → 长期占空比 50%，AGC 不漂移
- 只用「高电平的宽度」携带信息，对接收头的电平阈值不敏感
- 全世界最便宜的 433 模块都靠这套编码工作了几十年

`rc-switch` 库（https://github.com/sui77/rc-switch）用的就是同一套原理，
它的 protocol 1 定义 `{350, {1,31}, {1,3}, {3,1}, false}` —— 和下面的 `T=350µs`
完全一致。所以本协议的帧可以直接被 rc-switch 的嗅探工具抓出来看。

|---|---|---|

| 位周期 | `4T` = 1400 µs | 码率 ≈ **714 bps** |

## 3. 位编码

| 数据位 | 波形 | 高电平 | 低电平 |
|---|---|---|---|
| `0` | `▔▁▁▁` | `1T` (350 µs) | `3T` (1050 µs) |
| `1` | `▔▔▔▁` | `3T` (1050 µs) | `1T` (350 µs) |

```
   0:  ┌──┐                   1:  ┌────────┐
       │  │                       │        │
    ───┘  └──────────────      ───┘        └───
      1T    3T                    3T      1T
```

解码容差：**±45%**（即实测高/低电平落在 `0.55T ~ 1.45T` 内算 `1T`，
`2.55T ~ 3.45T` 内算 `3T`）。

## 4. 帧结构

```
┌───────────────────┬───────────────┬───────────────────────────────┐
│      前导码       │    同步头     │        载荷 (10 字节)         │
│ 20 个 2T 方波脉冲 │  1T 高 +      │  ID(7) FLAGS(1) SEQ(1) CRC(1) │
│ (高2T/低2T 交替)  │  16T 低       │                               │
└───────────────────┴───────────────┴───────────────────────────────┘
```

### 4.1 前导码 — 20 个 `2T` 脉冲（10 个完整周期）

```
   ┌────┐    ┌────┐    ┌────┐                ┌────┐
   │    │    │    │    │    │      ...       │    │
───┘    └────┘    └────┘    └──            ──┘    └─────────────
   2T    2T    2T    2T   （共 20 个脉冲 = 28.0 ms）
```

高电平起头，共 **20 个脉冲**（偶数个 → 最后一个必然是低电平收尾）。
这样接上同步头的「高 1T」时不会和前一拍同电平粘连。

作用有两个：让接收头 AGC 稳定下来（50% 占空比方波对 AGC 最友好）；
给解码器建立时间基准（连续多个 `2T` 脉冲是一道极强的噪声闸门）。

> **从 32 脉冲降到 20 脉冲的原因**
>
> 前导码的唯一物理作用是让超再生接收机的 AGC／峰值检波建立工作点，
> 实测建立时间在 1~2 ms 量级，32 脉冲（44.8 ms）远超所需 ——
> 这个数字来自早期照抄的通用遥控器协议，对单向 OOK 不是必需的。
> 降到 20 脉冲省下 **16.8 ms/帧**（帧长 162.75 → 145.95 ms）。
>
> **★ 主从必须同步**：主机 `OokReceiver.h` 的同步头搜索要求同步头之前
> 至少有 `OOK_PRE_WINDOW = 32` 个连续段、且其中至少 `OOK_PRE_MIN_MATCH = 20`
> 段落在 2T 窗口内。20 脉冲 = 40 段，对 32 段窗口仍有 8 段余量 ✓。
> 若把前导再砍到 **16 脉冲以下（= 32 段以下）**，`total < OOK_PRE_WINDOW`
> 就会失败 → 帧被整帧丢弃，而且**不产生任何错误日志**（只是 sync/ok
> 计数不涨），表现为「从机明明在发、主机一帧都收不到」的静默失联。
> 那种情况下必须同步把 `OOK_PRE_WINDOW` 调到 ≤ 2×脉冲数。

### 4.2 同步头 — `1T` 高 + `16T` 低

即 350 µs 高、5600 µs 低。这个「超长低电平」在正常数据里不可能出现
（数据位最长低电平只有 `3T`），所以解码器用它来定位帧起点。

接收端判定范围：该低电平落在 `10T ~ 26T`（3500 ~ 9100 µs）即认为是同步头。

### 4.3 载荷 — 10 字节，MSB first

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 7 B | `ID` | STC8 出厂唯一 ID（7 字节，按 STC-ISP 读出的顺序） |
| 7 | 1 B | `FLAGS` | 见下表 |
| 8 | 1 B | `SEQ` | 序号，每发一帧 +1，回绕 0~255 |
| 9 | 1 B | `CRC8` | 对 `ID[0..6] + FLAGS + SEQ` 计算 |

#### FLAGS 位定义

| 位 | 名称 | 含义 |
|---|---|---|
| 0 | `PRESENCE` | **1 = 检测到人**（核心开关量） |
| 1 | `TAMPER` | 1 = 防拆 / 异常（预留，从机暂不置位） |
| 2 | `LOWBAT` | 1 = 电池低（预留，从机暂不置位） |
| 3 | `PAIRREQ` | 1 = 从机主动请求配对 |
| 4-6 | 保留 | 固定 0 |
| 7 | `BOOT` | 1 = 该帧来自刚重启的从机（开机后前 8 帧）。**只用于诊断**，不参与任何报警判断；seq 只有 8 位，`seq` 变小既可能是重启也可能是回绕，靠猜无法区分 |

#### CRC-8 参数

| 参数 | 值 |
|---|---|
| 多项式 | `0x07`（CRC-8/ATM，x⁷+x²+x+1） |
| 初值 | `0x00` |
| 输入反射 | 否 |
| 输出异或 | `0x00` |

参考实现：

```c
uint8_t crc8(const uint8_t *d, size_t n) {
    uint8_t c = 0x00;
    for (size_t i = 0; i < n; i++) {
        c ^= d[i];
        for (int b = 0; b < 8; b++)
            c = (c & 0x80) ? (uint8_t)((c << 1) ^ 0x07) : (uint8_t)(c << 1);
    }
    return c;
}
```

## 5. 发送节奏

一帧空中时间：

```
前导码  20 脉冲 × 4T      =   80T  =  28.00 ms
同步头  1T 高 + 16T 低    =   17T  =   5.95 ms
载荷    80 bit × 4T       =  320T  = 112.00 ms
──────────────────────────────────────────────
合计                      =  417T  ≈ 145.95 ms
```

**段数**：协议时长 202 段，主机实际可捕获 201 段（载荷 159 而非 160）——最后一个段没有闭合边沿，尾部低电平被当作帧间隔丢弃。

主机 `need` 必须算 201：`need = i + 1 + OOK_PAYLOAD_BITS*2 - 1`。

从机发送策略：

| 场景 | 重复次数 | 说明 |
|---|---|---|
| 状态变化（有人/无人） | 3 次 | 立即发送（布防态） |
| 心跳 — 布防态（状态不变） | 2 次 | 每 2 s 一次（`APP_HEARTBEAT_MS 2000`） |
| 心跳 — 待机态（状态不变） | 2 次 | 每 10 s 一次（`APP_STANDBY_HB_MS 10000`） |

#### 待机态（standby）为什么要发心跳

从机**上电默认待机**：不采样 P3.3、继电器释放、`PRESENCE` 恒为 0。
但待机**不能**完全静默 —— 主机 `ZoneManager` 的离线门限是
`ZONE_OFFLINE_MS = 45000UL`，静默超过 45 s 该防区会被判离线，
屏上灰显、APP 报掉线，现场会直接当成设备故障。

所以待机期用 10 s 慢心跳维持「在线 + 无人」：

- 10 s 远小于 45 s，可容忍连丢 4 轮心跳仍保持在线
- 2 帧 ≈ 340 ms / 10 s → 占空比 3.4%（布防态 2 s 心跳是 16.7%）
- **没有引入新 FLAGS 位**：待机与布防在协议层都是 `PRESENCE=0` 的
  普通心跳，主机不需要任何改动就能兼容（新老固件可混用）

> 若要把「待机」和「无人」在协议层区分开，需要新增一个 FLAGS 位，
> 并**同时**修改 `src/master/OokReceiver.h` 与本文档 —— 只改一侧会
> 静默丢报文（flags 不匹配的帧会被判成未知设备）。当前刻意不做。

为避免 4 台从机长期同相碰撞，**从机必须在两帧之间插入基于自身 ID 的伪随机抖动**：

```
gap_ms = 20 + (ID[0] % 40)      // 20~59 ms，各从机自然错开
```

主机侧再按 `SEQ` 去重、按 `ID` 归档，偶发碰撞丢一两帧不影响功能。

最坏情况响应延迟：`146ms × 3 + 2 × 59ms ≈ 556 ms`，满足「1 秒内上报」要求。

## 6. 主机解码流程

主机用 ESP32-C3 的 **RMT 硬件接收**（1 MHz 时钟 → 1 tick = 1 µs）：

1. RMT 把每个电平跳变的时间戳写进环形缓冲，**CPU 零参与**
2. 空闲超过 12 ms → RMT 判定一帧结束，推一次数据
   （`OOK_IDLE_US 12000`，= `OOK_FRAME_GAP_US` 的别名。这个值直接决定解码
   延时：从机发完后主机要白等这么久才开始解码。帧内最长段是同步头
   16T ≈ 5.6 ms，12 ms 有 2.1 倍余量；也不能再降到 6 ms —— 弱信号下
   AGC 恢复慢会把 16T 拉长到 7~8 ms，必然切帧。取 12 ms 而不是 9 ms 的
   原因：从机两次发送之间的最短间隙是 `20 + (ID[0] % 40)` = 20 ms，
   而实测成簇丢帧时会出现「前一帧尾部被削 + 后一帧提前」，9 ms 下这种
   组合会把两帧粘成一帧然后整帧报废，12 ms 留出了安全余量）
3. 取出脉冲列表 → 找 `10T~26T` 的低电平作为同步头
4. 同步头之后按 `1T/3T` 规则逐位解码 80 bit
5. 校验 CRC-8，通过才交给防区管理器

不用 `rc-switch` 接收端：它在中断里用 `micros()` 攒时序，一帧 146 ms 全程占 CPU，会拖出刷屏卡顿。RMT 是纯硬件。
